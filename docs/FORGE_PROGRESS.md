# Nicokobo Forge 当前进度

## 2026-10-01 0.5.0 功能 API 与公共原生接入候选

在 0.4.0 机器模板 API 的基础上继续拆分功能边界。物品、效果、文本、机器注册／运行时、生命周期、模组、电量、液体、库存和周目存储各有明确入口；目录变化通知替代反复轮询。效果注册复用目录接入，补货独立为内部适配器；纯回调分派、模组准入合并、耗电判定和恢复不依赖游戏运行时。公共事件按需安装并共用 Hook，最后一个订阅退出时注销；各功能使用独立 Harmony ID，失败撤销或关闭门控，注册冲突保留现有原生对象。

模组矩阵 1.1.0、物流脉络 0.2.0、合成扩展 0.8.0 和机械飞升 0.1.8 已同步新 API。模组矩阵自管常规 Harmony 目标从 17 个降为 4 个；合成扩展从 13 个降为 10 个。义眼和持续成长旧档迁移已移除。框架拖放和合成夜间边界诊断仅 DEBUG 启用；内容特有的净水、解码、鉴价与销售接入仍保留。

246 项新机器／运行边界断言（此前 158 项及本轮 88 项）与 32 项当前互操作签名检查通过。发布包与调用工程结果见[本轮验证记录](probes/2026-10-01-api-boundaries-validation.md)。本轮为本地开发候选，未安装、未启动游戏；实际补丁接入、UI、过夜效果和新档保存重载仍待实机验收。API 说明见[职责文档](API_BOUNDARIES.md)。

## 2026-10-01 0.4.0 原版 UI 机器模板与统一资源事务候选

按用户要求整体替换机器 API，不保留旧接口兼容或旧存档迁移。`ForgeMachineDefinition` 声明输入、单一输出模板、电池、模组仓与手册；物品和液体容器可以同时输入，输出可以是有界物品仓或玩家装入的现有容器。框架统一处理组分／体积、动态产量、每批或每件耗电、资源预检、写后读回、反向恢复和故障隔离，每台机器每夜最多尝试一批。窗口复用原版组件和电池／模组接入接口，自定义机器仅需过夜和读档两个 Hook；原版熔炉追加配方按需额外安装投料和生产钩子。全局窗口创建与存档解码钩子、旧液体生命周期进度及兼容成员已移除。

合成扩展 K01–K05、原版熔炉扩展及机械飞升的 7 条 K05 追加配方均已迁移。配套候选为合成扩展 `0.7.0` 和机械飞升 `0.1.7`；K04 的灌装由框架处理，内容工厂先清空原版水瓶模板并读回。新增可编译 MachineTemplates 示例与新 API 文档。

158 条新增模板／液体计算／事务故障断言通过；Forge 核心、六个示例与四个调用工程 Release 编译通过；机械飞升 422、模块矩阵 89、物流 85、合成扩展 603 条领域检查通过；三个机核 Obfuscar 包及四份配套 Forge 哈希读回一致。框架 ZIP 与配套目录已生成，本轮未安装或启动游戏。原版 UI、拖放、实际过夜、模组效果和新档保存重载仍待实机验收，详见[本轮证据](probes/2026-10-01-machine-template-api-validation.md)。
