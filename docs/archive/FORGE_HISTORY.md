## 2026-10-01 0.6.0 机器槽位改原生接纳白名单

实机日志（26-10-1 08:25–08:30）在拖动物品经过自定义机器槽位时刷出 269 个错误块、538 条 `TargetException: Object does not match target type`，栈为 `ItemMouseDragHandler.StartDrag` → `GameGridInventory/GridPixelElement.MayHaveValidInventorySlot` → `InvokeFuncExtensions.InvokeAllReduce` → `Delegate.DynamicInvoke`。原因是 Forge 把 `mayInventoryAddItemFunc` 换成 `DelegateSupport.ConvertDelegate` 的托管委托：它在 il2cpp 侧报 `Func`3.Invoke`、目标是 `Il2CppToMonoDelegateReference`，反射调用必然类型不匹配。

本版删掉全部托管接纳委托：物品仓改用 `ContainerHelper.InitContainerItem` 的原生配方 ID 白名单，液体输入槽与容器输出槽改用 `ContainerHelper.AllowOnlyTaggedItem(slot, "LIQUID_CONTAINER_TAG")`。白名单由 `MachineAdmission.InputIds` 单一生成并冻结；模板与配方的槽位／容器条件退回到只在批次结算时校验。装配后逐槽读回实际委托写入 `[NicokoboForge/Admission]`，缺委托或 `interopBridge=True` 记 `WARN`。拖放探针改为覆盖 `GameInventory` 的全部具体重写，现在只用于发现外来托管桥。

32 项框架原生签名（新增两条 `ContainerHelper` 断言）、机器模板 42、批次计算／失败恢复 119、运行边界 88 项断言通过；机械飞升 422、模组矩阵 89、物流 L0=21／resource=37／power=27、合成扩展 629 项通过；六个示例、四个调用者编译与三个 Obfuscar 包通过。证据见[本轮记录](../probes/2026-10-01-machine-slot-admission-native-validation.md)。实机待验收：拖动不再刷错、`[NicokoboForge/Admission]` 全为 `interopBridge=False`、物品仓只接纳配方投入 ID、水槽只接纳液体容器，以及 `InitContainerItem` 对机器物品的容器初始化副作用。
