## 审查结果与修复

| 优先级 | 发现 | 处理 |
| --- | --- | --- |
| P1 | 机械飞升工坊仍把原生抽象 `GameInventory.Expel/UncheckedAccept` 交给 Harmony，属于此前零执行入口闪退的同类目标 | 改用四类具体背包；复用公共原生入口检查；生命周期与观察使用独立 Harmony ID，整组预检后安装，失败撤销本组 |
| P2 | 原共享图集加载器和单独名片／神经接口加载器直接覆盖同名缓存；后两者读回失败时还可能留下未管理资源 | 由公共图集 API 认领路径，拒绝已有缓存；逐 Sprite 核对身份，写后异常同样回滚，无法确认移除时保留资源 |
| P2 | 回调分派中的早期订阅注销后续订阅后，旧数组仍执行已注销回调；每次分派重新筛选排序并分配数组 | 缓存按信号排序的数组，在订阅变化时重建；旧快照跳过已注销订阅，保留新增延迟、嵌套调用及 ID 重用语义 |
| P2 | Forge 与机械飞升重复维护 ES3 规范化和文件读取；Forge 的 `ReadAllBytes` 在预检后没有限制实际分配 | 共享有界读取、严格 UTF-8、ES3 语法和唯一字段检查；业务结果仍由各自比较；不写存档 |
| P2 | 统一构建把默认 `INFO` 作为显式覆盖传给每个 Mod，冲掉机械飞升／矩阵的 `WARN` 默认 | 未指定参数或环境覆盖时按项目默认；明确覆盖仍生效；通过最终 DLL 元数据校验 |

本次重点检查公共生命周期、回调分派、机器注册／事务边界、资源加载、存档读取，以及四个 Forge 调用者的接入与构建。以上是已定位并处理的问题，不代表所有原生行为完成验收。

## 提取与迁移

- `ForgeAssetsApi` / `ForgeSpriteAtlas`：迁移六处图集，删除内容仓库的共享加载器副本和编译开关；图片、ID、滤镜、尺寸留在内容定义。
- `ForgeSaveReadbackApi`：迁移 Forge 成就和机械飞升 ES3 读取。机械飞升的状态、经济、奖励及原生库存比较保留在原项目；领域检查链接相同的公共纯逻辑源码。
- `ForgeHookApi.TryValidateNativeTarget`：开放 Forge 已有的原生入口预检，机械飞升工坊已接入。它不负责业务补丁、游戏构建门控或回调签名验证。
- README、能力范围、API 职责、开发说明、数值索引和文档索引同步整理；现行调用者版本纠正为源码版本，历史探针保留原日期与证据。检查数量集中在验证记录，接入文档通过链接引用。

接入示例及保留在内容侧的候选见 [SHARED_SERVICES.md](../SHARED_SERVICES.md)。
